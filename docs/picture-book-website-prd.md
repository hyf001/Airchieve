# 绘本网站产品需求文档

## 1. Executive Summary

### Problem Statement

儿童绘本阅读线上体验通常停留在静态翻页或简单音频播放，难以满足低龄儿童“听、看、互动、反复播放”的阅读习惯。同时，家长和老师缺少低门槛工具为特定孩子、班级主题或教学目标快速创建个性化绘本。

### Proposed Solution

建设一个面向儿童阅读的绘本网站，核心提供在线绘本播放阅读、音频朗读、亲子共读、会员订阅和绘本内容管理能力。平台同时提供绘本生成能力，支持家长和老师通过主题、已有故事或上传故事创建绘本，并选择角色形象和个人声音，生成可在线播放的定制化绘本。

### Core Domain Definitions

- 故事：纯文本内容资产，只包含标题、正文、适龄范围、主题标签、教育目标等文本元数据，不包含页面、插图、视频、音频、对白时间轴、对口型动画或播放结构。
- 绘本：基于故事生成，或由绘本模板替换角色形象和朗读声音后得到的可播放内容资产，包含页面结构、插图或视频、页面文字、音频朗读、对白、互动提示、学习卡片和播放配置。
- 用户头像：账号展示头像或用户上传的原始参考图片，不直接作为绘本生成结果使用；用户可以基于头像或参考图、画风和文字指令生成角色形象。
- 角色形象：用于绘本生成和模板角色替换的视觉资产，由系统预置或 AI 根据头像/参考图、画风和指令生成；每个角色形象必须绑定生成时使用的画风。
- 绘本模板：一个可被复用的现成绘本加角色说明，包含完整绘本内容、可替换角色、每页角色形象替换区域、默认角色形象和默认朗读声音；用户使用模板时只能替换角色形象区域和朗读声音，画风不可替换，除角色形象和朗读声音外的页面结构、文字、插图背景、视频、音效、互动提示和播放节奏必须保持一致。


## 2. User Experience & Functionality

### User Personas

- 儿童读者：3-10 岁儿童，主要通过家长或老师引导使用，偏好语音播放、图文并茂、节奏清晰的阅读体验。
- 家长：希望孩子获得高质量绘本内容，也希望围绕孩子姓名、兴趣、成长问题、个人角色形象、家人声音或家庭场景创建专属绘本。
- 老师：需要围绕课程主题、节日活动、班级行为习惯或教学目标快速创建绘本，并在课堂中播放、共读或使用老师自己的声音讲述。
- 多孩家庭：需要为不同孩子保存独立年龄、兴趣、阅读偏好和专属绘本库。
- 内容管理员：负责绘本上架、故事管理、音频管理、会员内容配置、审核 AI 生成内容。
- 平台运营：关注内容消费、创建转化、订阅转化和内容安全。

### User Stories

#### Story 1: 首页发现与快速开始

As a 家长、老师或儿童读者, I want to 在首页快速找到适合当前孩子或课堂的绘本、继续阅读或开始创建 so that 我不用先理解复杂功能就能进入阅读或生成流程。

Acceptance Criteria:

- 首页必须根据登录状态展示不同入口：未登录用户展示精选内容、免费试看、注册/登录入口；已登录家长展示儿童档案、继续阅读、个性化推荐和创建绘本入口；老师用户展示课堂播放、主题绘本和教学场景入口。
- 首页必须提供清晰的主操作入口，至少包含“开始阅读”“创建绘本”“继续上次阅读”；儿童阅读区域不得直接展示购买、订阅、充值等商业操作入口。
- 首页必须展示绘本搜索入口，支持按标题、主题、教育目标、年龄段、语言、阅读水平和免费/VIP 状态查找内容。
- 首页必须提供按年龄段、主题分类、阅读水平、语言、绘本类型和叙事风格浏览绘本的入口，例如 3-4 岁、5-6 岁、睡前故事、情绪管理、科普百科、中英双语、分级阅读。
- 首页必须展示多个内容推荐模块，MVP 至少包含精选绘本、新上架、热门播放、免费可读、会员精选、睡前推荐和中英双语推荐。
- 首页必须展示个性化推荐模块；当用户已选择儿童档案时，推荐必须参考年龄段、兴趣标签、阅读水平、阅读历史和收藏记录。
- 首页必须展示“继续阅读”模块，包括最近阅读绘本、上次播放进度、最近生成绘本和未完成生成任务。
- 绘本卡片必须展示封面、标题、适龄范围、预计播放时长、语言、标签、免费/VIP 状态，并提供进入详情页或直接播放的入口。
- 首页必须提供“按场景开始”的入口，例如睡前、亲子共读、课堂播放、情绪引导、习惯养成、英语启蒙、节日主题。
- 首页必须提供绘本生成的快捷入口，支持从一个想法开始、从系统故事开始、从我的故事开始、从绘本模板开始。
- 首页必须展示系统故事、系统形象、系统画风和系统声音的精选预览入口，帮助用户理解可生成内容的素材范围。
- 首页必须提供家长/老师可见的学习支持入口，例如共读提问、学习卡片、读后讨论、课堂主题包或活动建议。
- 首页必须支持活动、专题和运营推荐，例如节日专题、新书专题、情绪教育专题、传统文化专题和限时会员权益。
- 首页必须展示平台安全与隐私信任信息，包括无第三方广告、儿童阅读区无商业打扰、个人素材默认私密。
- 首页必须在移动端 375px 宽度下保持主要入口、搜索、推荐卡片和继续阅读模块可用，首屏必须能看到至少一个阅读入口和一个创建入口。

#### Story 2: 用户登录、注册与账号绑定

As a 家长或老师, I want to 使用微信或手机号快速登录/注册，并在需要时完成手机号绑定和真人验证 so that 我可以安全地保存儿童档案、个人素材、会员权益和绘本创作记录。

Acceptance Criteria:

- 未登录用户必须可以从首页、绘本详情页、播放器试看结束页、绘本生成流程和会员页进入登录/注册流程。
- 登录/注册弹窗或页面必须支持微信登录和手机号验证码登录两种方式，MVP 不要求密码登录。
- 手机号验证码登录必须支持新用户自动注册；当手机号首次登录时，系统必须创建账号并进入必要的初始化流程。
- 手机号登录必须包含手机号输入、短信验证码发送、验证码填写、倒计时重发、错误提示和登录成功反馈。
- 短信验证码必须区分注册/登录、手机号绑定、手机号换绑和手机号解绑等场景，验证码不得跨场景复用。
- 同一手机号、同一 IP 和同一设备短时间内频繁发送验证码时，系统必须限制发送频率并展示剩余冷却时间。
- 验证码校验失败次数达到限制时，系统必须临时阻止继续尝试，并提示用户稍后再试或重新获取验证码。
- 微信登录必须支持通过微信授权 code 获取用户身份；当微信身份未绑定任何账号时，系统必须自动创建新账号并绑定微信身份。
- 微信登录匹配账号时必须优先使用 unionid；无 unionid 时可以按当前应用 openid 匹配。
- 已登录用户必须可以绑定手机号，绑定前必须通过短信验证码确认手机号归属。
- 一个手机号同一时间只能绑定一个有效账号；当手机号已被其他账号占用时，系统必须阻止绑定并提示用户处理已有账号。
- 已登录用户必须可以换绑手机号，换绑流程必须验证旧手机号或当前登录身份，并验证新手机号验证码。
- 已登录用户可以解绑手机号，但解绑前必须确认账号仍保留至少一种可登录身份，例如微信登录，避免账号无法再次登录。
- 使用微信登录但未绑定手机号的用户，在进行会员订阅、分享含个人素材的绘本、创建个人声音、导出 PDF 或其他高风险操作前，系统可以要求先绑定手机号。
- 使用手机号登录但未绑定微信的用户，可以在账号设置中主动绑定微信，便于后续快捷登录。
- 登录成功后，系统必须恢复用户进入登录前的上下文，例如继续播放当前绘本、返回生成步骤、打开会员支付页或进入个人绘本库。
- 登录态必须支持退出登录；退出后本地不得继续展示需要登录的儿童档案、个人素材和会员权益数据。
- 登录/注册流程必须展示用户协议和隐私政策确认入口；新用户首次注册或首次微信登录创建账号时必须完成同意确认。
- 发送短信验证码、连续登录失败、异常设备登录、批量注册风险、创建个人声音、上传头像或参考图等场景必须支持触发真人验证。
- 真人验证可以采用滑块、图形验证、无感风控或第三方验证服务；验证方式必须适配桌面端和移动端。
- 真人验证通过后，用户应继续回到原操作流程；验证失败或取消时，系统必须保留已填写内容并允许重新验证。
- 真人验证不得出现在儿童阅读播放主流程中；如确需验证，必须引导家长在账号操作上下文中完成。
- 账号设置页必须展示当前已绑定的登录方式，包括手机号和微信，并提供绑定、换绑、解绑和退出登录入口。
- 管理员必须可以在后台查看账号的基础状态、注册时间、最近登录时间和登录方式摘要，但不得展示短信验证码明文或不必要的微信隐私信息。

#### Story 3: 在线播放绘本

As a 儿童读者, I want to 以播放形式阅读绘本 so that 我可以通过图画、字幕和朗读理解故事。

Acceptance Criteria:

- 绘本详情页必须展示封面、标题、适龄范围、预计播放时长、是否会员内容。
- 播放器必须支持播放、暂停、上一页、下一页、进度条和重新播放。
- 每一页必须支持图片、文字和音频朗读同步展示。
- 绘本必须支持中文、英文和中英双语三种文本展示模式。
- 中英双语模式下，每页必须同时展示中文文本和英文文本，并支持用户切换显示顺序。
- 自动朗读时必须支持当前句或当前段落高亮，帮助儿童跟读。
- 播放器必须支持朗读速度调节，MVP 至少支持慢速、正常、快速三档。
- 播放器可支持轻量场景动画、背景音乐和音效；用户必须可以关闭背景音乐和音效。
- 当页面包含形象对白时，播放器必须支持说话形象的嘴部对口型动画。
- 对口型动画必须与对应对白音频同步，播放暂停、拖动进度、切换页面时动画状态必须同步更新。
- 绘本阅读时必须允许用户选择系统内置声音或自己已上传/创建的声音。
- 当用户切换朗读声音后，播放器必须清晰展示当前使用的声音名称。
- 播放器必须在桌面端和移动端可用，移动端宽度 375px 下主要控件不可重叠。
- 免费用户访问会员绘本时，必须展示可试看页数和订阅引导。

#### Story 4: 亲子共读

As a 家长, I want to 和孩子一起阅读绘本 so that 我可以参与孩子的阅读过程并进行引导。

Acceptance Criteria:

- 绘本播放器必须提供“自动朗读”和“手动翻页”两种模式。
- 亲子共读模式必须突出当前页文字，并允许家长手动控制翻页。
- 每本绘本可配置 3-5 个共读提问或互动提示。
- 每本绘本可展示学习卡片，包含主题、教育目标、重点词汇和读后讨论问题。
- 共读提示必须可由后台创建、编辑和隐藏。

#### Story 5: 儿童档案与个性化

As a 家长, I want to 为每个孩子创建独立档案 so that 系统可以按年龄、兴趣和阅读水平生成更合适的绘本。

Acceptance Criteria:

- 家长必须可以创建多个儿童档案。
- 儿童档案必须支持昵称、年龄段、兴趣标签、阅读水平和常用教育目标。
- 儿童档案可以关联默认角色形象、默认声音和个人绘本库。
- 生成绘本时，用户必须可以选择一个儿童档案，也可以不选择档案直接生成。
- 选择儿童档案后，系统必须自动带入适龄范围、兴趣标签、阅读水平和推荐教育目标。
- 不同儿童档案必须拥有独立的阅读历史和收藏列表。
- 儿童档案信息默认仅家长账号可见。

#### Story 6: 绘本生成

As a 家长或老师, I want to 基于故事生成完整绘本，或基于绘本模板替换角色形象和朗读声音 so that 我可以为孩子或班级创建个性化阅读内容。

Acceptance Criteria:

- 绘本生成流程必须支持两种路径：基于故事生成绘本、基于绘本模板创作绘本。
- 基于故事生成绘本时，流程必须按步骤组织：选择或生成故事 -> 选择或生成角色形象 -> 生成/编辑分镜 -> 选择声音并生成语音 -> 播放预览。
- 基于故事生成绘本的故事来源必须支持四种：系统故事、我的故事、上传/粘贴故事、输入一个想法生成故事。
- 基于绘本模板创作时，流程必须按步骤组织：选择绘本模板 -> 替换模板角色形象 -> 选择朗读声音 -> 预览替换效果 -> 保存到个人绘本库。
- 用户生成故事时必须可以选择目标年龄段、故事长度、叙事风格和教育目标。
- 叙事风格至少包括睡前、冒险、童话、科普、幽默、情绪管理、习惯养成。
- 教育目标至少包括善良、勇气、分享、好奇心、情绪表达、规则意识。
- 用户必须可以选择生成语言，包括中文、英文和中英双语。
- 中英双语绘本必须为每页生成中文文本、英文文本和对应朗读文本。
- 当用户选择系统故事或我的故事时，系统必须展示故事标题、简介、适龄范围、主题标签和可用状态。
- 当用户选择绘本模板时，系统必须展示模板标题、简介、适龄范围、主题标签、教育目标、页数、可替换角色、默认角色形象、默认朗读声音、示例播放效果、可替换角色形象说明和画风不可替换说明。
- 绘本模板必须定义可替换角色，例如主角、朋友、家长、老师、动物伙伴；每个角色必须包含角色名称、角色说明、是否必填、出现页码、默认角色形象和每页角色形象替换区域。
- 基于绘本模板创作时，用户必须先为模板中的必填角色选择替换角色形象；角色形象可以来自儿童档案默认角色形象、用户形象库、系统形象库，或由用户上传头像/参考图、选择画风并输入指令后新生成。
- 用户替换模板角色形象后，系统必须只替换模板绘本中该角色对应的角色形象区域，并应用到所有关联页面。
- 基于绘本模板创作时，用户必须可以选择模板默认朗读声音、系统内置声音或自己已上传/创建的声音。
- 用户替换朗读声音后，系统必须使用新声音重新生成页面正文和对白对应的朗读音频，并保持原模板的文字、对白内容、对白时序和播放节奏不变。
- 基于绘本模板生成的绘本必须与模板绘本保持一致，除被替换的角色形象区域和朗读声音外，页面结构、正文、双语文本、画风、插图背景、视频、音效、对白内容、对口型动画时序、互动提示、学习卡片和播放节奏均不得改变。
- 基于绘本模板创作时，用户不得更换画风、插图背景、视频素材或页面构图；新生成或替换的角色形象必须与模板画风保持一致。
- 如果绘本模板某页包含多个可替换角色，系统必须明确展示该页可替换角色和对应角色形象区域，并允许用户逐页检查替换效果。
- 用户必须可以保留模板默认角色形象、替换全部可替换角色形象，或只替换指定角色形象。
- 当用户上传或粘贴故事文本时，MVP 最大 3000 中文字；超过限制时系统必须提示用户缩短。
- 当用户只输入一个想法时，系统必须先生成可确认的故事内容，并允许用户编辑后再进入下一步。
- 故事确认后，用户必须可以选择保留故事原角色形象、从自己的形象库选择角色形象、从系统形象库选择角色形象，或生成新角色形象。
- 用户必须可以将故事中的主要角色替换为自己的角色形象或系统角色形象。
- 如果没有可用个人角色形象，系统必须引导用户创建、跳过或选择系统形象。
- 生成新角色形象时，用户必须可以上传头像或参考图、选择画风并输入形象生成指令。
- 角色形象生成时必须选择画风；画风可以来自系统画风库，也可以由用户输入自定义画风描述。
- 画风选择必须至少提供系统预设选项，例如水彩、蜡笔、卡通、睡前温柔、国风、手绘线稿，具体画风名称可由运营配置。
- 角色形象确认后，绘本插图必须以角色形象绑定的画风为准生成；同一本绘本包含多个角色形象时，系统必须提示或处理画风一致性。
- 角色形象确认后，系统必须生成分镜，分镜至少包含每页标题、正文、画面描述、形象出场、对白标记和预计朗读文本。
- 如果页面包含对白，分镜必须标注说话形象、对白文本和对应语音片段。
- 用户必须可以编辑分镜内容，包括页数、页面顺序、页面文字、画面描述、形象出场和对白归属。
- 分镜确认后，用户必须可以选择系统内置声音或自己已上传/创建的声音生成每页语音。
- 语音生成必须支持中文朗读、英文朗读和中英双语朗读。
- 当用户选择自己的声音时，生成绘本的每页文字音频必须使用该声音。
- 语音生成完成后，系统必须进入播放预览，支持按页播放图片、文字、音频和对白对口型动画。
- 用户必须可以在播放预览后重新生成局部页面、重新生成局部语音，或一键保存到个人绘本库。
- 用户必须可以重新生成单页插图、单页文字、单页对白或整本语音。
- 系统故事、系统形象、系统画风、系统声音必须明确标记免费或 VIP 权益状态。
- 使用已有故事生成绘本时，系统必须尽量保留原故事的主线、形象关系和关键情节。
- MVP 阶段单本 AI 绘本长度限定为 6-12 页，单次生成耗时目标 P75 <= 90 秒。

#### Story 7: 故事库

As a 家长或老师, I want to 保存、上传和管理故事 so that 我可以先积累故事素材，再将故事生成不同版本的绘本。

Acceptance Criteria:

- 用户必须可以创建、编辑、删除和保存自己的故事。
- 用户必须可以上传自己的故事文本，MVP 支持纯文本粘贴或文本文件上传。
- 故事必须支持标题、正文、适龄范围、主题标签、教育目标和故事状态。
- 故事必须是纯文本内容资产，不包含页面结构、插图、视频、音频、对口型动画或可播放进度。
- 用户必须可以从故事详情页发起“生成绘本”。
- 同一个故事必须可以生成多个绘本版本，例如不同主角形象、不同角色画风、不同朗读声音、不同分镜版本。
- 故事详情页必须展示关联的已生成绘本列表。
- 故事库必须区分“我的故事”和“系统故事”。
- 系统故事库必须提供主题分类和灵感入口，例如睡前故事、经典童话、动物冒险、节日故事、情绪教育、课堂故事。
- 故事不得作为模板管理；需要复用完整绘本并替换角色形象或朗读声音的能力必须归入绘本模板。
- 系统故事必须支持免费和 VIP 两种权益状态；VIP 故事对非会员可展示简介，但生成或完整使用时需要订阅。
- 用户上传或创建的故事默认仅自己可见，不进入公开故事库。
- 用户上传故事时必须提示用户只上传自己有权使用的内容。

#### Story 8: 基于绘本创建类似作品

As a 家长或老师, I want to 在浏览喜欢的绘本时直接创建类似作品 so that 我可以快速复用喜欢的主题、结构或视觉风格来生成自己的绘本。

Acceptance Criteria:

- 绘本详情页、播放器结束页和绘本推荐区域必须提供“创建类似作品”入口。
- 用户点击“创建类似作品”后，系统必须进入绘本生成流程，并预填原绘本的主题、适龄范围、绘本长度和视觉风格参考。
- 预填内容必须允许用户编辑，用户必须可以更换故事、主角形象、朗读声音、教育目标和故事方向。
- 如果原绘本为会员内容，免费用户仍可进入创建流程，但生成或发布权限必须按会员权益控制。
- 创建类似作品时必须避免直接复制原绘本文字和图片，生成结果应作为新的个性化作品。
- 创建流程中必须清晰提示“类似”来源于主题、视觉风格或结构参考，而不是复制原作品。

#### Story 9: 画风管理

As a 家长或老师, I want to 从系统画风中选择或输入自定义画风 so that 我可以生成符合孩子或课堂场景的角色形象和绘本。

Acceptance Criteria:

- 画风必须作为独立资源管理，并在角色形象生成时作为必填配置绑定到角色形象。
- 用户生成角色形象时必须可以选择系统画风或输入自定义画风描述。
- 系统画风必须包含名称、示例图、描述、适用年龄段和权益状态。
- 系统画风必须支持免费和 VIP 两种权益状态；VIP 画风对非会员可预览，但使用时需要订阅。
- 绘本生成时必须以所选角色形象绑定的画风作为插图生成画风。
- 用户需要更换画风时，系统必须引导用户基于头像/参考图和新画风生成新的角色形象。
- 同一个头像或参考图必须可以搭配不同画风生成多个角色形象。

#### Story 10: 形象管理

As a 家长或老师, I want to 创建和管理自己的角色形象 so that 生成绘本时可以让孩子、家人或课堂形象成为故事主角。

Acceptance Criteria:

- 用户必须可以创建多个个人角色形象，并为每个形象设置名称、关系或身份标签。
- 每个形象必须至少包含名称、图片和绑定画风。
- 用户必须可以通过文字描述生成形象，例如“6 岁女孩，短发，喜欢红色裙子，活泼”。
- 用户必须可以上传头像或参考图片来辅助创建形象，并选择画风和输入生成指令；系统必须明确提示用户只上传自己有权使用的图片。
- 用户可以基于同一头像或参考图片生成多个不同画风的角色形象。
- 形象创建完成后必须进入用户的形象库，支持预览、重命名、删除和设为默认形象。
- 生成绘本时，形象选择器必须展示用户形象库和系统形象库中的可用形象。
- 系统形象必须支持免费和 VIP 两种权益状态；VIP 形象对非会员可预览，但使用时需要订阅。
- 删除形象时，已生成绘本中的历史图片不应被删除，但后续新绘本不能再选择该形象。
- 用户上传或生成的形象在默认情况下仅自己可见，不进入公开素材库。

#### Story 11: 我的声音管理

As a 家长或老师, I want to 上传和管理自己的声音 so that 绘本可以用我的声音为孩子朗读。

Acceptance Criteria:

- 用户必须可以创建多个声音，并为每个声音设置名称，例如“妈妈的声音”“老师的声音”。
- 用户必须可以上传自己的声音样本，并在上传前确认拥有该声音的使用授权。
- 声音创建完成后必须进入用户的声音库，支持试听、重命名、删除和设为默认声音。
- 系统必须提示用户声音样本的推荐录制时长、清晰度和环境要求。
- 声音创建过程中必须展示处理状态，例如“处理中”“可使用”“失败”。
- 生成绘本和阅读绘本时，声音选择器必须展示系统内置声音和用户自己的可用声音。
- 系统声音必须支持免费和 VIP 两种权益状态；VIP 声音对非会员可试听短样本，但使用时需要订阅。
- 删除声音时，已生成绘本中的历史音频不应被删除，但后续新绘本不能再选择该声音。
- 用户上传的声音在默认情况下仅自己可见，不进入公开声音库。

#### Story 12: 分享与导出

As a 家长或老师, I want to 分享或导出已生成的绘本 so that 我可以给家人、学生或课堂使用。

Acceptance Criteria:

- 用户必须可以将个人绘本生成只读分享链接。
- 分享链接必须支持关闭、重新生成和设置访问范围。
- 用户必须可以导出绘本为 PDF，MVP 可将高清 PDF 或打印成品作为付费/VIP 权益。
- 分享页必须保留绘本播放能力，包括文字、图片、音频和对口型动画。
- 用户分享含个人角色形象或个人声音的绘本前，系统必须提示确认隐私风险。
- 免费用户和会员用户的分享数量、导出次数和导出清晰度可由会员权益控制。

#### Story 13: 儿童安全与隐私

As a 家长, I want to 确认孩子使用的是安全、私密、无广告的阅读环境 so that 我可以放心让孩子阅读和播放绘本。

Acceptance Criteria:

- 儿童阅读和播放页面不得展示第三方广告、诱导消费弹窗或外链推荐。
- 儿童端不得直接展示购买、订阅、充值等商业操作入口；相关操作必须面向家长账号。
- 用户上传的故事、形象、声音和生成绘本默认仅账号内可见。
- 含个人角色形象或个人声音的绘本在分享、导出前必须展示隐私提醒。
- 系统必须提供内容举报入口，允许用户举报不适龄、侵权或异常内容。
- 用户必须可以删除自己的故事、形象、声音和个人绘本。
- 平台必须在产品文案中明确说明个人素材不会默认进入公开素材库。

#### Story 14: 绘本管理后台

As a 内容管理员, I want to 管理绘本、故事、音频和会员内容 so that 平台内容可以持续运营。

Acceptance Criteria:

- 后台必须支持绘本列表、创建、编辑、上下架、删除、搜索和状态筛选。
- 后台必须支持故事管理，包括系统故事、用户故事、故事标题、故事正文、适龄范围、标签、教育目标、权益状态、审核状态和关联绘本；故事管理不得包含页面、插图、视频、音频、角色位或播放结构配置。
- 后台必须支持绘本管理，包括绘本页、插图、音频、适龄范围、标签、教育目标、叙事风格、语言、角色形象画风、朗读声音来源和是否使用个人角色形象。
- 后台必须支持绘本页面级内容管理，包括页面顺序、页面标题、正文、中文文本、英文文本、双语显示配置、画面描述、对白标记、说话形象、朗读文本、背景音乐、音效和对口型动画素材状态。
- 后台必须支持配置绘本封面、简介、作者/来源、预计播放时长、试看页数、推荐权重、排序权重和上下架时间。
- 后台必须支持配置每本绘本的共读提问、互动提示和学习卡片，包括主题、教育目标、重点词汇、读后讨论问题、展示状态和排序。
- 后台必须支持配置系统画风，包括画风名称、示例图、描述、排序、启用状态、适用年龄段和免费/VIP 权益状态。
- 后台必须支持配置系统形象，包括形象名称、示例图、身份标签、描述、绑定画风、适用年龄段、排序、启用状态和免费/VIP 权益状态。
- 后台必须支持配置系统声音，包括声音名称、试听样本、支持语言、声音风格、适用年龄段、排序、启用状态和免费/VIP 权益状态。
- 后台必须支持配置主题分类、教育目标、叙事风格和推荐标签。
- 后台必须支持将已有绘本设为绘本模板，并支持绘本模板列表、创建、编辑、复制、预览、上下架、删除、搜索和状态筛选。
- 后台必须支持配置绘本模板基础信息，包括关联原型绘本、模板标题、简介、封面、适龄范围、主题标签、教育目标、语言、页数、默认朗读声音、权益状态和排序权重。
- 后台必须支持配置绘本模板的可替换角色，包括角色名称、角色说明、是否必填、默认角色形象、可用替换来源、出现页码和替换限制。
- 后台必须支持配置绘本模板的声音替换规则，包括是否允许替换朗读声音、可用声音范围、默认朗读声音和试听样本。
- 后台必须支持配置每页角色形象替换区域，包括关联角色、页面编号、区域位置、区域尺寸、遮罩范围、层级、圆角/裁切规则和替换后预览效果。
- 后台必须支持锁定绘本模板的非角色形象、非朗读声音内容；模板生成时不得修改原型绘本的页面顺序、正文、中文文本、英文文本、画风、插图背景、视频、音效、对白内容、互动提示、学习卡片和播放配置。
- 后台必须支持锁定绘本模板画风，模板创作流程不得向用户提供画风选择或画风重新生成入口。
- 后台必须支持逐页校验绘本模板，确保必填角色至少配置一个替换区域、替换区域不遮挡关键文字、替换区域与角色说明一致、每个替换区域可以正常预览。
- 后台必须支持预览模板角色形象和声音替换效果，管理员可以使用默认角色形象、测试角色形象和测试声音生成模板预览，检查每页替换位置、遮罩、裁切、层级和朗读音频是否正确。
- 后台必须支持统一管理内容分类、主题标签、兴趣标签、年龄段、阅读水平、教育目标、语言选项和叙事风格，避免前台筛选和生成配置不一致。
- 后台必须支持配置系统故事、系统形象、系统画风、系统声音的免费/VIP 权益状态。
- 后台必须支持会员内容标记，至少包含免费、试看、会员专享三种访问等级。
- 后台必须支持配置会员权益规则，包括绘本访问、试看页数、生成次数、故事数量、形象数量、声音数量、儿童档案数量、分享数量、PDF 导出次数和导出清晰度。
- 后台必须支持配置首页、分类页、绘本详情页、播放器结束页和生成入口的推荐内容、推荐故事、推荐绘本、推荐画风、推荐形象和推荐声音。
- 后台必须支持查看 AI 生成任务与生成结果，包括故事、分镜、插图、音频、对口型动画的生成状态、失败原因、重试记录和人工审核入口。
- 后台必须支持查看形象和声音内容的审核状态，但不得向普通管理员暴露用户原始隐私素材的非必要信息。
- 后台必须支持审核用户生成或上传的故事、绘本、图片、声音、分享链接和导出内容，并支持通过、驳回、隐藏、下架、封禁分享链接等处理动作。
- 后台必须支持处理用户举报，并记录处理结果。
- 后台必须支持管理分享与导出记录，包括分享链接状态、访问范围、关闭/恢复、PDF 导出状态和隐私风险标记。
- 后台必须支持查看基础内容运营数据，包括绘本播放量、完播率、收藏量、分享量、创建类似作品次数、生成转化率、订阅转化来源和举报数量。
- 后台必须记录内容创建人、更新时间、审核状态和发布状态。
- 后台所有写操作必须记录审计日志。

#### Story 15: 会员订阅

As a 家长, I want to 订阅会员 so that 孩子可以阅读更多绘本并使用更多绘本生成额度。

Acceptance Criteria:

- 会员页必须展示会员权益、价格、订阅周期和绘本生成额度。
- 系统必须支持免费用户、会员用户、管理员三类基础权限。
- 会员权益必须至少控制会员绘本访问、绘本生成次数、儿童档案数量、个人故事数量、个人形象数量、个人声音数量、分享数量、PDF 导出次数，以及 VIP 系统故事、VIP 系统形象、VIP 系统画风、VIP 系统声音的使用权限。
- 支付方式、价格、退款策略在当前阶段标记为 TBD，需业务确认后进入开发。

### Non-Goals

- MVP 不建设原生 iOS/Android App，仅建设响应式 Web。
- MVP 不支持多人实时协作编辑绘本。
- MVP 不开放第三方创作者投稿市场。
- MVP 不支持复杂游戏化学习系统，例如积分闯关、班级排行榜。
- MVP 不提供印刷下单和物流履约，仅预留 PDF 导出和未来打印服务入口。
- MVP 不承诺生成可商用出版级插画，AI 插图以线上阅读质量为目标。
